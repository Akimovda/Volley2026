# Баг промаха скролла к разделу дня на /events — полное расследование

Краткая версия — в CLAUDE.md, раздел "Баг промаха скролла к разделу дня на /events".

- **Симптом**: тап по чипу дня иногда докручивал МИМО — заголовок выбранного дня прятался под sticky-блоком, либо активным оставался соседний чип вместо реально выбранного. Особенно заметно при скролле ВВЕРХ, почти не проявлялось при скролле вниз — асимметрия была ключевой уликой.
- **Причина №1 — две РАЗНЫЕ границы для одной и той же вещи**: `alignedTop()` использовал `.mob-sticky.getBoundingClientRect().bottom` (низ ВСЕГО прилипшего блока — шапка + топбар фильтров + лента чипов), а `recomputeActiveDay()` по ошибке использовал `window.getFixedHeaderBottom()` — только высота `.fix-header`, заметно меньше. **Фикс**: единая функция `stickyBottom()`, используется в ОБОИХ местах.
- **Причина №2 — IntersectionObserver даёт entries только по ИЗМЕНИВШИМСЯ элементам, не полный снимок**: `entries.filter(e=>e.isIntersecting)` + `visible[0]` выбирал "самый верхний" ТОЛЬКО среди элементов, чьё пересечение изменилось В ЭТОМ вызове — не среди всех реально видимых секций. **Фикс**: IntersectionObserver теперь ТОЛЬКО триггер, выбор активного дня — прямой `getBoundingClientRect()`-запрос по ВСЕМ наблюдаемым секциям заново (максимальный `top` среди `top <= boundary`).
- **Причина №3 — гонка IntersectionObserver vs явный клик**: IO продолжает срабатывать ещё ~200мс ПОСЛЕ финальной scrollend-коррекции и переопределял только что зафиксированный кликом активный день. **Фикс**: `suppressObserverUntil` — окно 1500мс после явного клика по чипу, `recomputeActiveDay()` не выполняется вообще.
- **Причина №4 (тестовый артефакт, но чинить стоило)**: `chip.scrollIntoView({inline:'center'})` в некоторых движках задевал вертикальный скролл страницы как побочный эффект. Заменено на ручной расчёт `strip.scrollLeft += delta`.
- **Замена таймаут-угадайки на честное ожидание конца скролла**: `setTimeout(450)` угадывал длительность smooth-анимации. Теперь ждём `'scrollend'` (Chrome/Safari 16.4+) либо RAF-поллинг "scrollY не меняется 3 кадра подряд" как фоллбэк.
- Проверка (headless): клик по всем 10 чипам в обе стороны — во всех 20 переходах итоговый зазор 12-18px, активный чип совпадает с выбранным. Отдельно проверено в `.is-app` (notch 59px).
- **Гонка при первом рендере (2026-08-02)**: `syncStickyOffset()` пересчитывал `top` только на `resize`/`orientationchange`/`load`/`vp:header-resize` — недостаточно при догрузке шрифтов после `load`. Добавлены `document.fonts.ready.then(apply)`, `visibilitychange`, `ResizeObserver` прямо на `.fix-header`.
- **Разделитель топбар/чипы** (`.event-dates-ramka .events-topbar`, только `@media(max-width:767px)`): `border-bottom: 2px solid #2967BA`/`#E7612F` (тёмная) — та же пара, что в `body *::selection`. Исчезает вместе с топбаром при `.is-scrolled`.
- **`.events-topbar` (`data-aos="fade-up"`) против собственного `.is-scrolled{opacity:0}` (2026-08-02)**: AOS-стили в `lib.css` имели специфичность выше, чем у `.event-dates-ramka.is-scrolled .events-topbar{opacity:0}` — `opacity:0` при сворачивании никогда реально не применялся. Фикс — `opacity: 0 !important` + `visibility: hidden` с `transition-delay`. Подробности — `report_menu_history_and_topbar_2026-08-02.md`.
