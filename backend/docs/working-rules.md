## Правила работы
- В конце каждой сессии обновляй этот файл: добавляй новые находки, баги, паттерны
- Коммить изменения CLAUDE.md вместе с кодом
- Не дублируй — обновляй существующие секции
- НЕ изучай структуру проекта заново каждый раз — вся информация уже в этом файле
- Сразу приступай к задаче, используя контекст из CLAUDE.md
- **Отчёты по задачам (>50 строк итогов, вопросы к пользователю)** — файлом `report_*.md`/`deploy_*.md`/`diagnosis_*.md` в корень dev (`/var/www/volley-bot/backend`), НЕ в CLAUDE.md. Эти паттерны — в `.gitignore` (2026-07-16), **в git не коммитить никогда**, даже если явно попросят «закоммить отчёт» — сначала уточнить. Пользователь читает и удаляет сам; если такой файл пропал с диска между твоими действиями — это ожидаемо (пользователь прочитал и убрал), **не восстанавливать** из git-истории и не поднимать как проблему.

- **«Настройка App» (`/admin/apps`) — только white-label приложения** (svs и будущие, у каждого свои стили): всё хранится по бренду, применяется при `!$brand->is_default`; основной VolleyClub не трогать. После правки проверять curl с тремя UA: `SVSVolleyApp` (эффект есть), `VolleyPlayApp` и обычный браузер (эффекта нет).
- **`sudo` в сессии без пароля нет**: `./deploy.sh <бот> <env>` и `reload php8.3-fpm` запускает пользователь в СВОЁМ терминале БЕЗ префикса `!` (`!` только в чате со мной; в bash он отрицает команду, и она молча «не делает ничего»). После раскатки обязательно сверять результат: `cmp /opt/.../bot.py` с репозиторием, `ps -eo lstart`, `systemctl is-active`, лог.

## Диагностические скрипты и кэш маршрутов/конфига (добавлено 2026-10-24, после issues #78–#80 в GlitchTip)
- **Диагностический PHP-скрипт на dev или проде начинается с отвязки Sentry** сразу после bootstrap: `\Sentry\SentrySdk::getCurrentHub()->bindClient(\Sentry\ClientBuilder::create(['dsn'=>null])->getClient());`. Иначе любое исключение в скрипте уходит в общий проект GlitchTip и шлёт ложный алерт (так появился #80 от `/tmp/d2.php` — запрос к несуществующей колонке `users.organizer_status`). Имена колонок перед запросом сверять со схемой (`Schema::getColumnListing('table')`), а не писать по памяти. Закончив, удалять скрипт из `/tmp`.
- **Отдельный `route:clear` / `config:clear` перед `route:cache` / `config:cache` не нужен: команда очищает кэш сама** (`handle()` в `RouteCacheCommand`/`ConfigCacheCommand` начинается с `callSilent('route:clear')` / `callSilent('config:clear')`). Короткое окно без файла (`bootstrap/cache/routes-v7.php`, `config.php`) при пересборке неизбежно. Разовая ошибка `require(routes-v7.php)` или `config.php` во время деплоя — шум (так было с #78/#79 на dev 2026-10-24, count=1), если не повторяется вне деплоев. Отдельный clear перед ним окно только удлиняет. `view:clear && view:cache` оставляем: нет скомпилированного шаблона — Laravel компилирует его заново, это безвредно.
