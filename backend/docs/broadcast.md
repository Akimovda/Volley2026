## Трансляция, этап (а) А1 — площадки, состояние, реалтайм, токен-ссылки (2026-10-22, dev, не выкачено, UI нет)
- Таблицы (миграция `2026_10_22_100000`, бэкфилл внутри): `event_courts` (+`channel_key` — непредсказуемое имя публичного канала), `tournament_matches.court_id`, `broadcast_settings`, `broadcast_team_styles`, `broadcast_court_overrides`, `broadcast_links`. Строку `tournament_matches.court` НЕ трогаем (в ней служебные метки Grand Final/«Матч за N-M место» — не площадки). `CourtRegistry` (`app/Services/Broadcast`): `isRealCourt()`, `ensure()`, `backfill()`, `courtOfMatch()`; `TournamentScheduleService` пишет `court_id`. Friendly: площадка дня = первая площадка тура, видит матчи служебной стадии с `court_id IS NULL`.
- `CourtStateService::forCourt()` — один JSON и для `GET /o/{token}/state`, и для события `CourtStateUpdated` (ShouldBroadcastNow, канал `court.{channel_key}`, имя `.state`). Режимы считаются на сервере по меткам времени, клиенту отдаётся `mode_until`. Зависший live (>2 ч без активности) текущим не считается. Подача известна только при `match_set_starts`. Командная статистика — SUM из `match_player_stats`, `stats_basis:'attributed'`.
- Диспатч состояния: после очка/отмены/замены/старта партии (рядом с `TournamentMatchRallyUpdated`), в `TournamentMatchService::submitScore/resetScore` (+ матчи-преемники), при ручном переключении (`BroadcastControlService`). Сбой рассылки логируется и ввод счёта не ломает.
- Роуты `/o/{token}`, `/o/{token}/state` — в `routes/broadcast.php`, подключены через `then:` в `bootstrap/app.php` БЕЗ группы web (нет сессии/кук); middleware `broadcast.link:{role}` — любой отказ = 404. Выдача/отзыв ссылок — `BroadcastLinkService` (`canManageEvent`: владелец, staff, админ). Страница `/o/{token}` — заглушка до А2.
- Деплой: миграция + роуты + middleware-алиас → `merge`, `migrate --force`, `route:cache`/`config:cache`, `reload php8.3-fpm`, `queue:restart` одним блоком.
- **Оверлей (А2, 2026-10-22)**: `resources/views/broadcast/overlay.blade.php`, контроллер `BroadcastOverlayController::page`, lang `broadcast.php`. `?preview=1` — серый фон, `?lang=en`. Debugbar на роутах отключён. Клиент сам переключается в `mode_until` и подтверждает GET; WS не поднялся за 5 с → polling каждые 3 с. Сервер: решённый по очкам, но не финализированный матч → сразу `match_summary` (до последнего очка + N с). В payload добавлены `event` и `theme` (corner/template/show_set_scores/show_logos). Белая метка «на платформе volleyplay.club» внизу по центру (кроме off).
- **Настройка стрима (А3, 2026-10-22)**: `/events/{event}/broadcast` (`BroadcastSetupController`, `broadcast.setup.*`, права `canManageEvent`), подробности — `report/broadcast_a3.md`. Настройки оверлея хранятся по области: тур, если у тура есть площадки, иначе событие (`settingsScope()`) — оверлей читает их по `occurrence_id` площадки. Логотип команды в эфире — только загруженный. Публично показываем только `stream_urls` (`StreamLinksService`), токен оверлея — никогда. QR — локальный `public/assets/qrcode.js`. Тест-харнес для HTTP через `Kernel::handle`: между запросами `auth->forgetGuards()` + `session->forgetDrivers()`, иначе залипает пользователь.
- **Эфир из приложения (2026-10-23, dev, не выкачено)**: `broadcast_destinations` (court_id, platform vk|rutube|youtube|telegram|custom, server_url rtmp(s)://, `stream_key` — `encrypted` cast + `$hidden`, is_default) — ВХОД эфира, не путать со зрительскими `stream_urls`. Блок «Эфир из приложения VolleyClub» на `/events/{id}/broadcast` (ключ в HTML не отдаётся, «показать» — POST `.../destinations/{id}/reveal`, no-store). `GET /broadcast/camera` + `POST /broadcast/camera/{court}/start` (`BroadcastCameraController`) отдают данные в `Capacitor.Plugins.Stream.open()`; пункт «Трансляция» в меню организатора. Тесты `tests/Feature/BroadcastDestinationsTest.php` идут ТОЛЬКО на pgsql dev с откатом (`DB_CONNECTION=pgsql DB_DATABASE=volleyball SENTRY_LARAVEL_DSN=`), при смене пользователя между запросами — `auth->forgetGuards()` + `flushSession()`. Отчёт — `report/broadcast_camera_server.md`.

- **Ручная «Заставка» снимается сама (2026-10-22)**: `BroadcastControlService::releaseSplashOnPlay()` вызывается из `MatchLineupService::setSetStart()` и `MatchRallyService::recordPoint()` перед рассылкой состояния — обнуляет `manual_mode` ТОЛЬКО если он `splash` (`manual_match_id` сохраняется); `off`/`live`/итоги не сбрасываются. В JSON состояния есть `manual: bool` (пульт по нему сам убирает плашку «Ручной режим»). Причина: на тесте с приложения заставка, включённая до игры, держала табло скрытым при живом матче. `setSetStart()` теперь и сам переводит матч `scheduled → live` (как первое очко в `recordPoint`) — табло 0:0 с подачей сразу после расстановки; у матча без учёта состава `setSetStart` бросает исключение, live — с первым очком, как раньше.

## Трансляция, этап (б) — ведущий матча по токен-ссылке `/s/{token}` (2026-10-21, **выкачено на прод 2026-10-21 ~20:05 UTC**)
Отчёт — `report/broadcast_b.md`. Роль `scorer` в `broadcast_links` на площадку; срок = конец дня последнего матча площадки + 12 ч. Анонимная (имя 2–40 симв. в сессии+куке) или приглашение (`assigned_user_id`: только под этим аккаунтом, уведомление `broadcast_scorer_invited`).
- Роуты — `routes/broadcast.php`, группа `web` (гостевая сессия, обычный CSRF, исключений нет) + `scorer.link` (`ScorerLinkAccess`: отказ = страница «Ссылка недействительна»). `ScorerController` — hub `/s/{token}` + экран `/s/{token}/m/{match}` + JSON-действия. Матч должен принадлежать площадке ссылки (`CourtStateService::matchesOfCourt`), иначе 404; тайбрейк/king_beach/завершённый — отказ; переоткрытия нет.
- **Экран и действия — один код с организатором**: `_partials/rally_screen` + `rally_live` получают набор адресов `RallyUrls::forOrganizer|forScorer`; данные/фрагмент — `RallyScreenService`; валидация+вызовы очка/отмены/старта/замен — `RallyInputService` + `RallyActor` (user/name/linkId); итог счёта — `MatchFinalizeService::finalize()` (без редиректов), завершение стадии — `StageCompletionService` (в `TournamentController` остались делегаты). Новое действие ввода добавлять в `RallyInputService`, а не копировать в контроллеры.
- Аудит: `recorded_by_link_id` (FK → broadcast_links, nullOnDelete) + `recorded_by_name` (+ `recorded_by_user_id`) во всех таблицах ввода; в журнале «✍ имя».
- **Ловушки**: (1) старый `GET /s/{slug}` (редирект сезонов) перехватывал токен — у него `where` с негативным lookahead на 40 симв. `[A-Za-z0-9]`; (2) безымянный `throttle:N,M` делит счётчик по IP со всеми такими же → у ведущих именованные лимитеры `scorer-ip`/`scorer` (иначе душили бы оверлей `throttle:120,1`), объявлены в `AppServiceProvider::boot()`; **при `route:cache` файлы `routes/*.php` НЕ исполняются — `RateLimiter::for()` и любые другие регистрации внутри роут-файла молча пропадают (прод/dev с кешем роутов дают 500 `Rate limiter [..] is not defined`); HTTP-тесты гонять с `route:cache`**; (3) swal в проекте — кнопки `.btn--confirm`/`.btn--cancel` (не `.swal-button`); (4) `@json([... __() ...])` с массивом внутри ломает blade — собирать в `@php`.
- Тесты без боевых данных: HTTP через Kernel с cookie-jar и настоящим CSRF в транзакции с откатом; для браузера — мини-сервер в том же процессе с открытой транзакцией (`stream_socket_server` + `Kernel::handle`), rollback при остановке. Очередь кук `app('cookie')->flushQueuedCookies()` между «устройствами», лимитеры — в Redis (копятся между прогонами).
- **Деплой этапа (б) на прод (2026-10-21)**: прод на ветке `production`, merge `origin/main` (коммиты `bfa40ca0`, `3e35c9ff`, `572fe067`) → `migrate --force` (2 миграции: `2026_10_24_100000` — имя с датой 10-24 по ошибке, переименовывать нельзя, уже применена на dev и прод; `…100100`) → `config/route/view:cache` → `reload php8.3-fpm` → `supervisorctl restart volleyplay-queue:*` одним блоком; composer/npm не нужны. Проверено через nginx: `/s/{неверный токен}` → 404 «Ссылка недействительна», `/events`, `/`, `/login` → 200, оверлей с чужим токеном → 404; GlitchTip после выкатки чистый (issue `VOLLEYPLAY-BACKEND-2A` — вчерашняя dev-500 до переноса лимитеров, закрыт как ложный). **Первый инцидент на dev (не на проде)**: после `route:cache` 500 `Rate limiter [scorer-ip] is not defined` — лимитеры были в `routes/broadcast.php`, при кеше роутов он не исполняется; перенесены в `AppServiceProvider` ДО выкатки на прод. Живой ввод по реальной ссылке на проде не проверялся (тестовые роуты/данные на проде запрещены) — смотреть GlitchTip и `match_rally_events.recorded_by_link_id` после первого реального использования. `origin/production` запушен (fast-forward `4ac38881..9f46732c`, внутри весь накопленный хвост прошлых выкаток).

## Трансляция: «Мои каналы трансляции» — постоянные ключи организатора (2026-10-23, dev, не закоммичено/не выкачено)
- `broadcast_channels` (organizer_id, platform, label, server_url, `stream_key` encrypted+`$hidden`, is_default; первый канал — по умолчанию) + `broadcast_destinations.channel_id` (nullOnDelete; у назначения-канала `server_url`/`stream_key` = NULL, колонки стали nullable). Старые назначения (свои url/key) работают как раньше и имеют приоритет над каналом по умолчанию.
- Резолв цели эфира — `BroadcastTargetResolver::resolve()` (единая точка для `/broadcast/camera` и `/start`): валидное назначение площадки (default → первое) → иначе канал по умолчанию владельца события → иначе ошибка. Осиротевшее назначение (канал удалён: `channel_id NULL` и `server_url NULL`, `isOrphan()`) → `/start` отдаёт 422 `code=no_channel` «Выберите канал»; совсем пусто → прежний `no_destination`.
- Права: CRUD каналов и reveal — только владелец и админ (`BroadcastChannelController`, страница `/broadcast/channels`, роль organizer/admin). Помощник видит в «Настройке стрима» только платформу+название каналов владельца события (без server_url/ключа), выбирает канал `POST …/courts/{court}/channel` и запускает эфир; reveal назначения-канала для помощника — 403. Ключ канала уходит только в ответ `/start` (no-store).
- Удаление канала, выбранного на площадках: без `confirm=1` → 409 `in_use` + `used`=число площадок; с confirm — удаляет, назначения осиротевают.
- Тесты: `tests/Feature/BroadcastChannelsTest.php` (+ старый `BroadcastDestinationsTest`). **При закешированном конфиге (`bootstrap/cache/config.php`) phpunit.xml игнорируется → 419 на всех POST**; запускать, временно убрав кеш конфига: `mv bootstrap/cache/config.php /tmp/c.bak; DB_CONNECTION=pgsql DB_DATABASE=volleyball SENTRY_LARAVEL_DSN= VIEW_COMPILED_PATH=/tmp/vc vendor/bin/phpunit …; mv /tmp/c.bak bootstrap/cache/config.php`.
- Деплой: миграция + роуты + новые классы → merge, `migrate --force`, `route/config/view:cache`, `reload php8.3-fpm` одним блоком.

## Чек-лист трансляции + «▶ Матч начался» (2026-10-24, dev, не закоммичено/не выкачено)
- **Чек-лист** вверху `/events/{id}/broadcast` (`broadcast/_checklist_steps.blade.php`, расчёт — `Services/Broadcast/StreamChecklist`): 1) матч есть (friendly — матч игры в этом туре; турнир — матч с командами на площадке выбранного тура; если матчи есть, но без площадки — подсказка «назначьте ниже»), 2) активная ссылка оверлея у каждой активной площадки (кнопка «Выдать ссылку» кликает существующие `#bc-issue-day`/`.bc-issue`), 3) назначение площадки или канал по умолчанию — через `BroadcastTargetResolver::resolve()`; кнопка «Добавить канал» только владельцу/админу, 4) подсказка запуска. Нет матча → блоки ниже в `.bc-rest.bc-dim` (opacity, НЕ disabled) + «Сначала создайте матч»; всё готово → `<details>` «✓ Трансляция готова». Та же подпись под кнопкой «Настройка стрима» на `game.manage`/`tournament.setup` (`StreamChecklist::hasMatches`).
- **«▶ Матч начался»**: `tournament_matches.started_at` (миграция `2026_10_24_120000`; ставят и «Матч начался», и первое очко/`setSetStart` при scheduled→live). `RallyInputService::matchStart/matchUnstart` (+ роуты `tournament.matches.rally.match.start|unstart`, `scorer.match.start|unstart`), кнопка в `rally_live` (`$canMatchStart` — scheduled, нет очков, нет учёта состава; при track_lineup роль играет «Начать партию»), swal-подтверждение в `rally_screen`. Идемпотентно по состоянию; `client_request_id` кешируется 10 мин — запоздалый повтор после «Отменить начало» не запускает матч заново. Отмена запрещена при любых очках/заменах/расстановке (`RallyInputService::hasPlay`). Live без очков = табло 0:0 уже обеспечено `CourtStateService::liveMatch` (по статусу live).
- Тесты: `tests/Feature/MatchStartTest.php`. **Не убирать `bootstrap/cache/routes-v7.php` на работающем dev даже на секунды — реальный запрос даёт 500 и алерт (GlitchTip #78)**; после новых роутов — `route:cache`.
