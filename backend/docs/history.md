### Деплой 2026-07-09 — три фикса закрыты (dev→prod)
Коммиты `25558e3`, `1551a65`, `56fc794`, `e1fb7a9`, смёржены в `production` (`6d630d1`). `composer install`/`npm`/`migrate` не требовались (без изменений composer.lock/миграций/Vite-JS). `config:cache`+`route:cache`+`view:cache`+`reload php8.3-fpm` выполнены.
1. **Гендер-квота при смене позиции организатором** (`EventRegistrationGuard::checkGenderQuotaForUser`, см. «Управление регистрациями») — проверено на бою (событие 380, occurrence 12253): реальная квота 4/4 женщин на `setter` блокирует корректным текстом. Находка: в этом конкретном событии `event_role_slots.setter.max_slots=4` **численно совпадает** с `gender_limited_max=4`, поэтому старый slot-лимит и так блокировал на этом же пороге — для чистой проверки именно новой гендерной защиты slot временно поднимался до 6 внутри тестовой транзакции (не в бою). Реальная брешь проявляется только когда slot-лимит НАСТРОЕН ШИРЕ гендерной квоты — обычная конфигурация организатора, не текущий частный случай события 380.
2. **`waitlist:cleanup-expired`** (см. «Лист ожидания») — задеплоена, `dailyAt('04:15')` подтверждён в `schedule:list`. Реальное удаление на проде выполнено 2026-07-09 09:33 UTC: 16 записей (occurrence starts_at 29 апр — 15 июня 2026), протокол dry-run зафиксирован перед удалением. `occurrence_waitlist` после — 0 строк.
3. **King Beach edit-форма + фикс GameCalculator-затирания** (см. «registration_mode — значения и приоритет») — проверено на бою (событие 392): форма рендерится с полями min/max (15/25), общие team-поля скрыты. Сохранение реальных данных проверялось **через транзакцию с откатом** (не прямым commit) — ручная пересборка ~40 полей формы для настоящего сохранения на живом платном турнире (взнос 1250₽, старт через 2 дня) сочтена неоправданным риском ради проверки, не относящейся к сути фикса; транзакция даёт те же гарантии без риска. Результат: max_players/min_players/registration_mode/role_slot не затираются.
- **Паттерн для будущих боевых проверок фиксов**: если тест подразумевает мутацию реальных данных (смена позиции регистрации, сохранение формы события) — оборачивать в `DB::beginTransaction()`/`DB::rollBack()` вместо прямого вызова, особенно если код по пути шлёт реальные уведомления (push/Telegram/VK) живым пользователям. Прямой (не откатываемый) вызов оправдан только для чтения (рендер страницы, SQL-проверки) или для операций, где организатор явно и осознанно просил именно боевое сохранение конкретной, полностью проверенной записи.

### Деплой 2026-09-28 — white-label бренды (feature) + инцидент 500 site-wide на проде
Коммиты `81946d72`…`c1ea17a7` (7 шт., см. «White-label / бренды приложений» ниже). `composer install`/`npm run build` не требовались (без изменений composer.lock/package.json — новые классы в существующем неймспейсе `App\` находятся через PSR-4 fallback даже с `--optimize-autoloader` без `-a`/`--classmap-authoritative`, `composer dump-autoload` не обязателен для этого случая). Были 3 новые миграции + сидер `BrandSeeder`.
- **Инцидент**: между `git merge origin/main` (мгновенно меняет файлы) и завершением `php artisan migrate --force` (заняло несколько секунд) образовалось окно, в которое реальные запросы ловили `SQLSTATE[42P01]: relation "brands" does not exist` — потому что новый `DetectBrand` middleware (глобальный, `bootstrap/app.php`) обращается к таблице `brands` на КАЖДОМ запросе. Алерт Uptime Kuma «Down 500» сработал именно в это окно (issue GlitchTip `VOLLEYPLAY-BACKEND-I`, 7 попаданий за 13 минут, до завершения `migrate`).
- **Второй, более узкий инцидент сразу следом**: `route:cache`/`config:cache`/`view:cache` были выполнены НЕ сразу после `merge`+`migrate`, а через несколько минут (после диагностики первого сбоя) — в этот разрыв реальный визит на `/admin/users/{id}` (страница с новым `route('admin.users.brand.update')`) поймал `RouteNotFoundException`, т.к. рантайм читал устаревший закешированный файл роутов с прошлого деплоя (`VOLLEYPLAY-BACKEND-J`, 2 попадания). `php artisan route:list` эту проблему НЕ показывает — она читает роуты напрямую из файлов, не из закешированного рантайм-файла.
- **Ошибочный первый диагноз (задокументирован как урок)**: в моменте я решил, что причина — устаревший composer-classmap, и запустил `composer dump-autoload --optimize`. Сайт действительно ожил сразу после этого, но НЕ из-за автозагрузчика — просто к этому моменту `migrate` уже успел завершиться. Проверка через GlitchTip API (см. «Мониторинг и бэкапы» в `~/.claude/CLAUDE.md`, токен `GLITCHTIP_API_TOKEN` есть только в dev `.env`, на проде отсутствует) — единственный надёжный способ узнать реальную причину постфактум, «сайт снова отвечает 200» ничего не доказывает о том, что именно было причиной.
- **Проверка на побочные эффекты после инцидента**: `events`/`event_occurrences`, созданные в окне сбоя — 0 записей; `admin_audits` в окне — 0 записей (значит форму никто не сабмитил, только словил ошибку при чтении страницы); `failed_jobs` — пусто. Оба падения были на GET-запросах (чтение), не на записи данных — обрывов транзакций не было. Правило на будущее — см. блок выше в общем разделе «Деплой».

## Сессия 2026-10-17: схема турнира в анонсе, черновик мероприятия, чипы дат в Safari
- **Командный турнир: `event_game_settings.subtype` при создании был `4x2` вместо реальной схемы** (событие 448, анонс VK «Формат 4-2» при фактическом 5-1). `createGameSettings()` брал `game_subtype`, которого у турнира нет (схема — `tournament_game_scheme`), и падал на дефолт `4x2`; путь редактирования уже брал `tournament_game_scheme`. Исправлено fallback'ом (коммит `3ec1746b`). **VK-анонсы не редактируются** — уже опубликованный пост с неверным форматом исправляется только вручную. Старые командные турниры могли получить `4x2` так же — не проверяли.
- **Форма создания мероприятия** (`events/create.blade.php`): кнопка «Сохранение...» разблокируется через 45 с с сообщением (раньше висела вечно); не блокируется, если отправку отменила валидация шага; сбрасывается при возврате из bfcache. Тексты — `events.create_saving|create_save_stuck`. Случай Кравцовой 16.10 (~13:06 UTC): `POST /events` в nginx-логе не было вообще — запрос не дошёл до сервера (завис в WebView), серверной причины нет. Фото/обложка грузятся отдельным AJAX (`/user/photos`), в форме только ID.
- **Серверный черновик мастера** (`event_drafts`, один на пользователя, 30 дней): `EventDraftController` (`events.draft.save|restore|destroy`), автосохранение формы с клиента (пауза 2,5 с, смена шага, `visibilitychange`/`pagehide` через `sendBeacon`; только `isTrusted`-события), баннер «продолжить/удалить» на `/events/create`, восстановление — redirect с `withInput($payload)` + `wizard_initial_step`, т.е. через штатный `old()` (не воссоздаём поля в JS — зависимые селекты/show-if отлажены на `old()`). Черновик удаляется в `EventCreateController::store()` после успешного создания. Не сохраняется без `title`. **Не проверено вживую в браузере/приложении** (только сквозной HTTP-тест на dev).
- **Чипы дат на /events: iOS Safari переставал скроллить после 2–3 тапов** (чип подсвечивался, страница не ехала, ошибок в консоли нет). Причина: у `html` `scroll-behavior:smooth` + нативный `scrollTo({behavior:'smooth'})` и `scrollend` — Safari молча игнорирует новый scrollTo при незавершённой нативной анимации. Исправлено своей rAF-анимацией `animateScrollTo()` (цель пересчитывается каждый кадр, новый тап/касание отменяют предыдущую, `scroll-behavior` на время анимации = auto); `replaceState` в try/catch. Подтверждено пользователем на iOS 26.6.2. **Правило: скролл к якорю на страницах с липкой шапкой — не на нативном smooth.** Вибрации в браузере нет (Vibration API в iOS Safari не поддерживается); в приложении глобальный haptic на клики — `capacitor-native.js`, решение владельца: оставить как есть.
- **Диагностика в headless Chromium с UA iOS Safari (без суффикса приложения)** воспроизводит часть Safari-только поведения: показывается баннер «Скачать приложение» (`swal`, перекрывает все касания до закрытия; кнопки `.swal-footer .swal-button-container:first-child button`). Скомпилированные Blade-шаблоны на dev принадлежат `www-data` — для тестов под `appuser` `VIEW_COMPILED_PATH=/tmp/vc`.
