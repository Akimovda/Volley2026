## Виджет на сайт — оформление (2026-10-06)
- **Один рендер для всех вариантов**: `widget/_content.blade.php` (карточки с фото как на `/events`) + CSS из `WidgetStyleService::css()`. iframe (`widget/iframe`), JS-вариант (`/widget/events.js` — рисует `html` из `/api/widget/events` в **shadow-root**) и предпросмотр в ЛК показывают одно и то же. CSS самодостаточный (px, свои `.vw-*`), `style.css` сайта НЕ подключается — его rem зависит от `html{font-size:58%}`, в shadow-root/на чужом сайте всё раздулось бы. Адаптив — `@container`, не `@media`.
- **Поля оформления** — единый источник `WidgetStyleService::groups()` (тип, дефолт, границы): по нему же валидация (`sanitize()` — цвет `#rrggbb`, int в границах, enum из списка, текст без тегов), дефолты и форма на `/profile/widget` (цикл по группам, подписи `profile.wst_f_*|wst_g_*|wst_v_*|wst_p_*` RU+EN). **Новое поле = строка в `groups()` + ключи `wst_f_<key>` в обоих lang + (если нужно) правило в `css()`/`_content`.** Хранится в `organizer_widgets.settings.style` (миграции не было); `settings.color` и `show_slots/show_location` остались для обратной совместимости (у виджетов без `style` дефолты берут `color` как акцент).
- Пресеты (`presets()` — light/dark/sport/minimal) только подставляют значения в поля формы через JS, на сервере хранятся итоговые поля. Предпросмотр — `POST /profile/widget/preview` (по несохранённой форме, без записи; при отсутствии будущих мероприятий — `WidgetEventsService::sampleEvents()`), iframe `srcdoc`, высота по `postMessage`.
- Данные мероприятий вынесены в `WidgetEventsService` (кеш-ключ теперь включает show_*; фото — первое из `event_photos`, `event_thumb`, абсолютный URL, фолбэк `/img/beach|classic.webp`).
- `script()` раньше подставлял `key` в JS без экранирования — теперь `json_encode`.
- Страница ЛК: `row row2` заменён на `row`, у `.card` внутри форм — `height:auto` + явный `margin-bottom` (иначе блоки слипались).
- **Раскладка по содержимому (2026-10-06, по заданию школы svs.team)**: `layout` = `cards|list|wide` (list — строки БЕЗ фото, wide — горизонтальные карточки), `columns_max` (ранее `columns`, легаси мапится в `resolve()`; это МАКСИМУМ, сетка `auto-fit minmax(min(100%, card_min), 1fr)` + `max-width = min(columns_max, число карточек) × card_max`), `card_min_width/card_max_width`, `align`, `theme` (`custom` по умолчанию = поля как есть; `light|dark|contrast` перекрывают цвета поверхностей на рендере через `WidgetStyleService::forRender()`), `show_icons` (ранее `meta_icons`; гасит эмодзи в строках/плашках/заголовке и 🙈). Одно мероприятие → узкая карточка, при ширине блока ≥560px — широкая горизонтальная (container query на `.vw-root`, не `@media`).
- **Стилизация снаружи**: все значения в CSS — `--_x: var(--vw-x, серверное)`; сайт задаёт `--vw-accent|card-bg|card-radius|title-color|meta-color|button-bg|button-color|gap|card-min|card-max|wide-max|…` на `#volley-widget` (проходят сквозь shadow-root). `--vw-accent` красит и заголовок, и кнопку. `part=` на root/header/cards/card/photo/title/meta/badge/button/empty/footer. data-атрибуты контейнера `data-layout|columns|theme|accent|limit` уходят query-параметрами в `/api/widget/events` (и `/embed/org/{id}`) и проходят ту же `sanitize()`; `data-color` игнорируется. Переменные и атрибуты описаны на `/profile/widget`.
- **Виджет ≈ карточка /events (2026-10-06)**: порядок `card_order` (`photo_first`|`title_first` — название+адрес над фото; в горизонтальной карточке шапка скрывается, заголовок в теле, дубль через `.vw-head`/`.vw-body-head`), блоки с опциями (всё по умолчанию ВЫКЛ, чтобы старые виджеты не изменились): `show_organizer` (имя/ник, email не показываем), `badge_subtype|gender|age|pay|rated|status`, `show_progress` (+`progress_color`), `show_weather` (только кеш `WeatherService::forOccurrence`, как на карточке; нужна фото-раскладка), `show_free_label`. Данные — `WidgetEventsService::extras()` (подписи на языке запроса → **локаль входит в ключ кеша**, версия ключа `v3`). Пресет `site` («Как на /events») включает всё. Скрыть заголовок — `header_show` / `data-header="0"`.
- **Язык виджета** (`lang`: `ru` по умолчанию | `en` | `auto`; `data-lang`): раньше подписи шли по Accept-Language посетителя чужого сайта и на русском сайте выходило «0 of 16 players», «Beg — Pro». Теперь `styleFor()` ставит `app()->setLocale()` ДО сборки данных; `auto` = язык браузера.
- **Приватные мероприятия в виджете (2026-10-08, событие 436 / svs.team)**: виджет не фильтрует `is_private`, а ссылка `events.show` для приватного даёт 404 всем, кроме организатора/staff/админа. Теперь для приватных с `public_token` ссылка — `/e/{token}?occurrence=` (`events.public`; посетителю пишется доступ в `event_private_accesses`), ключ кеша `widget_events_v7_`. Следствие: виджет публикует токен приватного события всем посетителям сайта-хозяина.
- **Баг времени (исправлен)**: виджет показывал `starts_at` как есть (UTC) — на 3 часа раньше московского времени на `/events`. Теперь `setTimezone(occ.timezone ?: event.timezone)`. Дата — на языке запроса.
- Проверка вёрстки: HTML страницы с `attachShadow` + `innerHTML` из `_content` → headless Chrome `--screenshot` (см. сценарии в этой сессии: 1/2/5 карточек, 360/768/1200, контейнер 320px, `--vw-accent` на хосте).
- Не проверено вживую в браузере на реальном сайте-хозяине (shadow-root проверен только рендером HTML в headless Chrome); у владельца dev нет Pro — тест через `OrganizerSubscriptionService::activate()` в транзакции с откатом.

## White-label / бренды приложений (feature, добавлено 2026-09-28)
Второе нативное Capacitor-приложение «SVS Volley» (волейбольная школа Семёнова) ходит на тот же бэкенд `volleyplay.club`, что и основной VolleyClub. Различаются только суффиксом в `User-Agent` (нативная обёртка/иконка/сплэш — в мобильном репозитории, не здесь). Задеплоено на прод 2026-09-28 (см. «Деплой 2026-09-28» выше — там же инцидент при накатке).
- **Таблица `brands`**: `slug` (`volleyplay`/`svsvolley`), `ua_suffix` (`VolleyPlayApp`/`SVSVolleyApp`), `display_name`, `site_title`, `logo_day_path`/`logo_night_path`, `og_image_path`, `is_default` (ровно одна запись true — `volleyplay`). Сидер `BrandSeeder` (запускать вручную — `db:seed --class=BrandSeeder`, не в расписании).
- **`App\Models\Brand`**: `Brand::cached()` — `Cache::rememberForever('brands.all', ...)`, инвалидация на `saved`/`deleted`. `Brand::detectByUserAgent($ua)` — первый бренд, чей `ua_suffix` входит в UA, иначе бренд с `is_default=true` (бросает исключение, если такого нет вообще — сигнал, что сидер не запущен).
- **`App\Http\Middleware\DetectBrand`** — ГЛОБАЛЬНЫЙ middleware (`bootstrap/app.php`, `$middleware->append(...)`, НЕ `appendToGroup('web', ...)` — нужен и вне группы web), кладёт бренд в `app()->instance(Brand::class, $brand)` на каждый запрос. Доступ из blade — `app(\App\Models\Brand::class)`, НЕ через `View::composer('*')` (см. `reference_cold_start_diagnosis.md` в памяти — один из трёх источников замедления cold start на iOS).
- **`users.brand_id`/`events.brand_id`** — nullable FK на `brands`, `NULL` = легаси/volleyplay (обратная совместимость, существующие данные не трогали). Назначается организатору вручную через `/admin/users/{id}` (карточка «Управляет приложением», `AdminRoleController::updateUserBrand()`, пишет в `admin_audits`). Мероприятие наследует бренд от РЕАЛЬНОГО организатора (`EventStoreService::store()`, `event->organizer_id` — может отличаться от создающего пользователя, см. `resolveOrganizerIdForCreator()`), НЕ от создателя.
- **Фильтр ленты `/events`** (`EventIndexService::occurrenceIndex()`) — white-label приложение (не `is_default`) видит только мероприятия организаторов своего бренда; основное приложение (volleyplay) видит ВСЕ бренды. Приватность (`is_private`/`event_private_accesses`) — ортогональная ось, не трогали, применяется как раньше ДО бренд-фильтра.
- **Логотип/title/og-meta** — `voll-layout.blade.php`: для `is_default` поведение не изменилось (тот же инлайн-SVG); для white-label — картинка бренда через партиал `components/_brand_logo_img.blade.php` (day/night вариант, переключение CSS `body.dark`), переиспользуется в 3 местах (шапка desktop/mobile + футер). **Ловушка: `@else@include(...)@endif` без пробела Blade НЕ компилирует как директиву** — печатает буквальный текст `@include(...)` в HTML вместо рендера партиала (найдено и исправлено 2026-09-28, коммит `c1ea17a7`). Всегда добавлять пробелы вокруг соседних директив без скобок между ними; проверять не только `php -l` на скомпиленном (он не ловит эту ошибку, т.к. непереваренный текст директивы — валидный PHP-текст), а искать в реальном HTML-ответе ожидаемую разметку (`grep` по классу/атрибуту, который должен был отрендериться).
- **PDF-экспорты** (`events/registrations/pdf.blade.php`, `dashboard/org_players_audience_pdf.blade.php`) — лого берётся от `$event->organizer->brand`/бренда текущего организатора, фолбэк на `web-app-manifest-192x192.png`.
- **НЕ сделано (осознанно, проговорено с пользователем)**: email (тема Jetstream берёт `APP_NAME=VolleyBot` из `.env` — отдельная несостыковка названий, не в скоупе), Telegram/VK/MAX боты (отдельные процессы вне репозитория), favicon (не подменяется), `WidgetPublicController`/публичные страницы локаций-школ/sitemap (не фильтруются по бренду), текстовый футер «VolleyPlay.Club» в турнирном PDF, авто-простановка бренда организатору при регистрации через конкретное приложение (только вручную через админку).

## Настройка App — темы white-label брендов (feature, добавлено 2026-09-29)
Админ-раздел «📱 Настройка App» (`/admin/apps`, `AdminAppController`, вью `admin/apps/{index,edit}.blade.php`, пункт в админ-меню `voll-layout.blade.php`, ключи `admin.app_*`/`ui.admin_apps` RU+EN). Список иконок брендов → экран бренда: 9 цветов × день/ночь (основной акцент, вторичный акцент, фон страницы, фон карточек, текст + меню: фон шапки/меню, текст пунктов, заголовки разделов, подчёркивание/активный пункт, иконки шапки и их hover), логотипы день/ночь, иконка приложения, живой предпросмотр (JS).
- **Хранение**: `brands.theme` (json `{day:{primary,secondary,bg_page,bg_card,text}, night:{…}}`, пусто = по умолчанию) + `brands.app_icon_path`. Файлы — `storage/app/public/brands/{slug}/…`, в БД путь `storage/brands/...` (как у `logo_*_path`, через `asset()`). Удаляются только файлы из `storage/brands/`, статику из `public/icons` не трогаем. Каждое сохранение пишется в `admin_audits` (`brand.theme.update`).
- **Как применяется**: `App\Services\BrandThemeService::css($brand)` — `style.css` НЕ меняется и переменных в нём нет. Сервис РАЗБИРАЕТ `style.css`, находит все декларации с базовыми цветами (`#2967BA` синий, `#E7612F` оранжевый, `#FFB171` = светлый оттенок оранжевого — вычисляется из вторичного акцента, `#C8DCFF` фон страницы, `#2C2C2C`/`#CACACA` текст, `#161721`/`#222333` ночные фоны) и переизлучает только их с цветами бренда. Селекторы с `body.dark` → ночная палитра; дневное правило без `body.dark` получает ещё и ночной override с префиксом `body.dark ` (иначе дневной цвет протекал бы в ночь). Фоны карточек/`.ramka` (градиенты rgba) и все 4 цвета меню генерируются адресными правилами в `surfaceCss()` (не через карту hex — у меню и акцента один и тот же `#2967ba`, разделить их заменой цвета нельзя; правила идут ПОСЛЕ автогенерированных и специфичнее, поэтому выигрывают). Результат кэшируется по `md5(theme)+filemtime(style.css)` — при правке `style.css` кэш обновляется сам. Инжект — `<style id="brand-theme">` сразу после `style.css` в `voll-layout.blade.php`, только если `$brand->hasTheme()`.
- **Ловушки**: (1) новый цвет, который нужно сделать настраиваемым, надо добавить в `BrandThemeService::BASE` (это базовые hex из style.css) — иначе генератор его не увидит; (2) цвет, встречающийся в style.css в другом смысле (например `#fff` на кнопках), в карту намеренно НЕ включён — `bg_card` для дня задаётся адресно (`.card`, `.ramka`); (3) основной бренд (`is_default`, volleyplay) в разделе НЕ показывается, `edit`/`update` для него — 404 (тема применялась бы на сайте для всех посетителей, логотип у него встроен инлайн-SVG); если понадобится — снять `abort_if` и фильтр в `index()`; (4) в формах на `.form` отступы между соседними `.btn`/`inline-block` элементами через `margin` НЕ работают (кнопки «слипаются») — оборачивать в `display:flex; gap:...`; (5) проверять вживую: `POST /admin/apps/{id}` в скрипте требует `ValidateCsrfToken::except(['*'])`, иначе 419.
- **Аудит «настройки ничего не меняют» + фон тремя слоями + свой CSS/JS (2026-10-22, dev, не выкачено)**: главный дефект — фон страницы НЕ меняется, потому что `bg_page` подменял лишь `#c8dcff`, т.е. ПЕРВЫЙ цвет градиента шапки; второй цвет шапки, градиент центра (`.main-container`, `#e7f0ff→#fff`) и подвал (`footer`, `position:fixed;z-index:-1` на десктопе, static на мобильных) его не касались. Теперь в форме 6 цветов на режим: `hdr_from/hdr_to` (`.top-section`), `body_from/body_to` (`.main-container`), `ftr_from/ftr_to` (`footer`), «от → до» сверху вниз, одинаковые = сплошной (`BrandThemeService::zonesCss()`, селекторы `body …`/`body.dark …` специфичнее style.css). `bg_page`/`bg_page_to` убраны из формы, но остались в `BASE` (ранее сохранённые темы работают; при следующем сохранении формы они сбрасываются). **Свой CSS и JS на приложение**: `brands.theme.custom_css|custom_js` (≤30000 симв., без миграции), только для не-основного бренда. CSS выводится ПОСЛЕДНИМ в `<style id="brand-theme">` (`</style` нейтрализуется), виден в живом предпросмотре; JS — `<script id="brand-custom-js">` перед `</body>` (IIFE + try/catch, переменные `brand.slug`/`brand.path`, `</script` нейтрализуется), в предпросмотре только после сохранения. Для CSS под одну страницу у `<body>` бренд-приложения атрибуты `data-brand="<slug>"` и `data-path="/events"`. Основной бренд (`is_default`) не затронут никак (проверено curl с UA `VolleyPlayApp`/браузер: ни стилей, ни скрипта, ни атрибутов). **Методика аудита (повторяемая)**: для каждого ключа темы генерировать CSS с уникальным цветом, подставлять в страницы headless-Chrome и искать цвет в `getComputedStyle` ВСЕХ элементов (+`::before/::after`). **Ловушка: перед сканом отключать `transition/animation` (`*{transition:none!important}`)** — иначе у элементов с `transition: all` computed-значение остаётся старым и настройка ложно выглядит «мёртвой» (так первый прогон дал 38 «мёртвых», после отключения — 10, и все они зависят от состояния: hover/focus/`status-live`/`alert-success`/`.bg-danger`/отмеченный чекбокс — на гостевых страницах элементов нет). Реально мёртвых цветов/токенов нет; архитектурное ограничение — всё держится на подмене базовых hex из style.css (цвет, которого нет в `BASE`/токенах, настроить нельзя → для этого теперь свой CSS).
- **Деплой**: миграция `2026_09_29_120000_add_theme_and_icon_to_brands_table` + новые роуты + пункт меню в шапке для админов → `merge`+`migrate`+`route:cache`/`config:cache`/`view:cache` ОДНИМ блоком (иначе админ ловит `RouteNotFoundException` на любой странице с шапкой), затем `reload php8.3-fpm` (новые классы).
- **Фон-градиент, шары, цвет алертов (2026-10-05)**: `bg_page_to` — конец градиента `body` (`linear-gradient(160deg, bg_page → bg_page_to) fixed`; пусто/равно `bg_page` = сплошной, `pageBackgroundCss()`); `orb_main` (`.orb-1/.orb-2`) и `orb_center` (`.orb-3`) — размытые шары фона на десктопе (без своей настройки следуют акцентам через общую hex-карту). Цвет текста `alert-info/-warning/-danger` и `score-pill` выводится из primary/secondary в `colorMap()` (`mix()` с чёрным днём / белым ночью) — иначе при несиневом акценте текст оставался синим. `alert-success` (зелёный) от акцентов не зависит. Предпросмотр на странице бренда показывает info/danger-алерты и поле ввода.
- **Иконки шапки** (вход/аватар, почта, гамбургер, тема) по умолчанию красятся `#E7612F` (= вторичный акцент, меняются вместе с ним) и `#2967ba`/`#FFB171` на hover; отдельные настройки `menu_icon`/`menu_icon_hover` перекрывают их адресными правилами (hover — внутри `@media (hover:hover) and (pointer:fine)`, как в style.css).
- **Меню бренда (добавлено 2026-09-29)**: `brands.menu` (json `{hidden:[пути], links:[{title_ru,title_en,url,place:site|user,new_tab}]}`), блок «Пункты меню» на экране бренда (галочка = пункт ПОКАЗЫВАЕТСЯ, по умолчанию все отмечены; в БД хранится `hidden` = каталог минус отмеченные; меню сохраняется только если в форме есть маркер `menu_form`, иначе частичный POST скрыл бы всё). Скрывать можно только пункты из каталога `config/brand_menu.php` (ключ = путь; **при добавлении/переименовании пункта в шапке — синхронно править каталог**, иначе пункт нельзя будет скрыть, а изменённый путь перестанет скрываться). Пункты админа в каталоге нет намеренно (нельзя закрыть себе доступ к «Настройка App»), «Выйти» — тоже.
  - **Свои ссылки** — партиал `components/_brand_menu_links.blade.php` (`place=site` — в конец колонки `column-two` меню сайта, видно и гостям; `place=user` — в конец колонки `column-main` меню пользователя, только авторизованным, перед «Выйти»). URL проверяется регэкспом `^(https?://|/(?!/))\S*$` (запрещены `javascript:` и `//host`), максимум `brand_menu.max_links`=15, название по локали (EN, если задано, иначе RU). `new_tab` → `target=_blank rel="noopener noreferrer"` (в Capacitor-WebView внешний `_blank` может открыться в системном браузере).
  - **Ловушка**: новый файл в `config/` на окружении с закешированным конфигом (`bootstrap/cache/config.php`, dev тоже) не виден до `config:cache` — симптом: `Rule::in(config(...))` пустой и валидация отвергает любое значение.

## Токены темы, шрифт бренда и схемы уровней (2026-10-07, dev, не задеплоено, не закоммичено)
- **Токены элементов** — `config/brand_tokens.php` (группы → токен = ОДИН элемент + свойство; `{M}` = `body`/`body.dark`). `BrandThemeService::tokenCss()` выводит их ПОСЛЕ общей темы с `!important`; в `brands.theme[day|night]` хранятся с префиксом `t_`. Пустое значение = не применяется. Новый элемент = строка в конфиге + ключи `admin.tok_*` (RU+EN); контроллер/вью не трогать. Первый пакет: лента дней, фильтры/селекты, карточка, бейджи. Остальные страницы — добавлять по мере надобности.
- **Классы-маркеры без CSS** (`days-strip`, `card-title` вне `.event-card`, `menu-icon-pin/organizer`, `icon-calendar/level/men`) не стилизуются сами — токены на них ссылаются только через родителей (`.event-col-icon`, `.menu-icon svg`).
- **Шрифт бренда** — `brands.theme.font` (ключ из `brand_tokens.fonts`), файлы OTF в `public/assets/fonts/` (Pragmatica Next XXL, веса 100/400/900, не в git-истории вопроса лицензии). `fontCss()` — @font-face + font-family. Нужен деплой самих файлов на прод.
- **Схемы уровней** — таблица `level_schemes` (owner_type brand|organizer, 7 строк, принимаются только целиком), `LevelLabelService` (организатор → бренд → стандарт/spb), `level_name()/level_name_short()` принимают 3-й аргумент `$organizerId`, `level_pill_style()` — inline-цвет пилюли. Применено в `events/_card` и виджете (`widget_events_v7_`, `organizer_id` в данных). Остальные места, где вызывается `level_name()` без organizerId, показывают стандартные названия (только бренд-схема). API для приложения: `GET /api/app/level-scheme?organizer_id=`. UI: `/admin/apps/{brand}` (бренд) и `/profile/widget` (организатор, Pro).
- **Упрощение экрана «Настройка App» (2026-10-09)**: секция «Акценты по ролям» убрана из формы и из валидации контроллера (код ролей в `BrandThemeService` остался, но не используется; у брендов сохранённых ролевых цветов не было); токены сведены 71 → 45 (один токен = несколько правил: `input_*` красят поля, списки и рамки чекбоксов, `card_icon` — все акцентные иконки карточки и т.д.; info/danger-алерты и «середина» прогресса следуют общим акцентам); мини-предпросмотр удалён (есть живой iframe); панели День/Ночь переключаются кнопками над iframe, группы токенов — `<details>`. Старые ключи токенов в сохранённых темах просто игнорируются. Новый токен — по возможности добавлять правилом в существующий, а не новым полем. После правки `config/brand_tokens.php` — `config:cache`.
- **Акценты по ролям (2026-10-07)**: `theme[day|night].primary_<роль>` / `secondary_<роль>` (роли — `BrandThemeService::ROLES`: buttons, links, tabs, forms, frames, alerts, menu, bg). `build()` карты замены цветов считает по роли; каждое правило/селектор style.css относится ровно к ОДНОЙ роли (`roleOf()` по имени класса; неопознанное = `other`, всегда следует общему акценту, ~80 классов). Пусто = общий акцент; без ролевых значений вывод побайтово эквивалентен прежнему (проверено сравнением наборов деклараций). Приоритет: токен элемента (`t_*`, !important) → акцент роли → общий. Новый класс с акцентом попадёт в роль автоматически по имени; если нужна иная роль — править `roleOf()`.
