## Погода на мероприятиях на улице (feature, добавлено 2026-09-29)
- **Флаг `events.is_outdoor`** (bool, nullable: NULL = не указано → погоды нет, false = зал, true = улица). Чекбокс «На улице (не в зале)» — шаг 1 создания (блок «Климатические условия», виден для ВСЕХ типов; `is_snow` остался только для beach+game) и страница редактирования (`event_management_edit`, отдельная карточка). Уровень события, не occurrence (наследуется всеми турами серии). Проходит через `EventCreateValidator`, `EventStoreService`, `EventManagementController::update()`, prefill копирования (`EventsController`).
- **Источник — OpenWeather, бесплатный `/data/2.5/forecast`** (5 дней, шаг 3 ч; ключ `OPENWEATHER_API_KEY` в `.env`, `config/services.php` → `services.openweather.key`, в git не коммитить). Дальше 5 дней от сегодня погоды нет — это ограничение тарифа, не баг. Новый ключ активируется до пары часов (до этого `401 Invalid API key`).
- **Архитектура**: `App\Services\WeatherService` — `refreshLocation()` качает и кладёт в Cache (redis) ПО ЛОКАЦИИ (`weather:owm:loc:{id}`, TTL 6 ч); `forOccurrence()` только ЧИТАЕТ кеш (без сети — безопасно из карточек списка), берёт ближайший к `starts_at` слот (сдвиг ≤1.5 ч), иначе null. Прогрев — `weather:refresh` (`everyThreeHours`, `routes/console.php`; локации ближайших 5 дней неотменённых уличных occurrence; `--dry-run`). Без ключа/при ошибках сайт погоду просто не показывает.
- **UI**: партиал `events/_partials/weather_badge.blade.php` (карточка, сверху по центру картинки, `.event-weather` в style.css) + строка «Погода на время мероприятия» в `events/show/info.blade.php`. Значок — эмодзи по коду погоды OpenWeather (`WeatherService::icon()`), осадки показываются от 10 %.
- **Плашки на картинке карточки** (`.event-price`, `.event-weather`) — единый стиль: фон `rgba(0,0,0,.75)`, белый текст, в обеих темах. Иконка луны — inline SVG (`WeatherService::iconHtml()`, наследует цвет), остальные — эмодзи. `events.weather_title` = «Погода»/«Weather» (используется и как подпись строки на странице мероприятия).
- У старых мероприятий флаг NULL — организаторы отмечают при редактировании (авто-бэкфилл не делали: пляж бывает и в зале).

## Страницы /about и /help, скриншоты, APK в футере (2026-10-02)
- **`/about` — тексты в `lang/{ru,en}/pages.php` → ключ `about`** (массивы: `audiences`, `sections.<id>` с `title/intro/cards/blocks[left,right,left_title,right_title]`, `cities`, `steps`, `bots`). `pages/about.blade.php` только рендерит их циклом; порядок секций — `$sectionOrder`, кнопки под секциями — `$sectionButtons` (id → `[url, ключ_подписи, класс]`). **Новая секция/пункт = правка ОБОИХ lang-файлов с одинаковой формой массива** (проверка: сравнить `array_keys` рекурсивно RU/EN — без пропусков и кириллицы в EN). Города на странице — «города запуска» (в т.ч. где игр ещё нет, по решению владельца), не «где идут игры».
- **Ловушка `target="_blank"` в нативном приложении**: `route()` отдаёт АБСОЛЮТНЫЙ URL, поэтому проверка `str_starts_with($url,'http')` помечает `_blank` и внутренние кнопки → в Capacitor они открываются во внешнем браузере. Внешней считать только ссылку с `parse_url($url, PHP_URL_HOST) !== request()->getHost()`. Кнопки магазинов (App Store/RuStore) внутри приложения скрыты: `html.is-app .about-store-buttons{display:none}`.
- **Кнопки на `/about` (итог 2026-10-02): страница — НЕ набор кнопок.** Заливными (`btn`) остаются только главные действия: hero «Найти мероприятие», две CTA в карточках «Зачем игроку/организатору», «Подать заявку на организатора» (тип `primary` в `$sectionButtons`, размер `btn-small`) и финальная «Найти мероприятие →». Все остальные переходы — **текстовые ссылки в стиле сайта** `<a class="blink b-600">…→</a>` (тип `link`, по умолчанию), в hero — белые (`.about-hero-link`: `:before` белое, `:after` полупрозрачное, т.к. `blink` рисует подчёркивание псевдоэлементами). Магазины — картинки-ссылки (`/img/appstore.png`, `/img/rustore.png`, 256×72; `.about-store-logo`; в тёмной теме `filter:invert(94%)`), мессенджеры в блоке ботов — круглые значки провайдеров `<span class="provider-card__icon icon-tg|vk|max about-bot-icon">` (SVG подставляет `lib.js` из объекта `icons` по классу `icon-<ключ>`; в lang-массиве `bots` первый элемент — это КЛЮЧ иконки `tg|vk|max`, не эмодзи). Тип элемента `$sectionButtons`: `'link'` | `'primary'` | путь к картинке (только секция `app`).

## Страницы игроков, профиль, уровни, аватары (итоги 2026-10-02)
- **Окно «турниры» в колонках «Игры» (`/players/rating`) и «Игр вместе» (`/players/teams`)** — `App\Services\PlayerTournamentListService` (`forPlayers()/forPairs()/forRosters()`; 3 запроса на страницу, без N+1), общие партиалы `players/_games_modal` + `_games_script` (fancybox inline; ссылки `.games-link` с `data-key/data-title/data-count`, данные `$gamesData`/`$gamesHeads` через `@json`). В списке: название турнира → `route('tournament.public.show', event)?tab=results&occurrence_id=`, «дата · Матчей · Побед», **место**: 🥇🥈🥉 (1–3) или «N место». Учитываются только командные матчи (`team_home_id/away_id`), завершённые, без тай-брейков, зачётные (как `TournamentMatch::ratable()`); **индивидуальные форматы (king_beach) в окно не попадают** — число в колонке может быть больше суммы матчей в окне. Шапка окна: аватары участников (пара — два игрока на отдельных строках; команда — капитан последней версии состава).
- **Место в окне — только у ЗАВЕРШЁННОГО турнира** (`places()`): все стадии `completed`, ЛИБО ничего не идёт (`in_progress`), оставшиеся стадии пусты (0 матчей — не запущенный плей-офф) и дата тура старше суток. Источник мест — `TournamentStatsService::calculateFinalClassification()`; ошибки расчёта глотаются (место — украшение, страница не падает).
- **Статистика сохраняется после удаления турнира**: `player_pair_stats`, `player_career_stats` и `player_rating_history` (там `event_id` обнуляется `nullOnDelete`) — «сироты»; окно тогда пустое, подпись `players.games_modal_missing` («статистика сохранилась, турниры не найдены»). На проде так у пляжных пар (пляжные турниры удалены владельцем 2026-09-27/28). Пересчёт `rebuildAll` стёр бы эти данные — делать только по явному решению.
- **Колонка «Связки/Команды» (`/players/teams`) — БЕЗ flex в ячейке**: игрок = `display:table` + `table-cell` (`.pair-player/.pair-ava/.pair-name`), аватар `max-width:none` (глобальный `img{max-width:100%}` в ячейке по содержимому схлопывал его в 0).
